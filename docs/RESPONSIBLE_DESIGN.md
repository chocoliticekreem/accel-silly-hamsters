# Responsible design

Smart City Sim is "PostHog for shop energy": each week an independent Shoreditch shop owner gets 1–3 changes to opening hours and lighting, with impact (visits, kWh, £), confidence, evidence and Approve/Reject; Claude agents (one per shop, plus an analyst) propose each change and test it first in a deterministic 14-day simulation of the real area.

By design a shop sees only its own data plus anonymous area benchmarks; the BID (our sales channel) and the council (phase 2) get anonymised area totals only, never one shop's numbers.

Status key. **Enforced**: code blocks it and a test proves it. **Partial**: code blocks it on one path; another path is still open (the gap number says which). **Mock only**: frontend demo, not in the backend.

## What we never do

- Change a shop's real hours or lights. The owner does that; we only simulate and suggest.
- Show one shop another shop's data, plans or advice.
- Coordinate hours or prices between shops. There is no price lever at all.
- Give a council, landlord or BID numbers for a single shop, or let a council use our data for licensing, business rates or enforcement.
- Track or profile real people. Every simulated person is synthetic.
- Present a simulation as a guarantee.
- Let an agent spend past its cap or act without a log line.

Where the code does not yet enforce one of these, it is listed below.

## Known gaps

1. **No login yet.** Anyone who knows a shop id can open its report, insights and store page, and post Approve or Reject for it. The firewall is per page, not per person. On the hosted demo `READ_ONLY` blocks training and optimise, but not `POST /api/decision` or `POST /api/apply`. A posted decision's free-text reason also reaches that shop's agent prompt. Real shops need a login per shop, and BID and council roles that can call area endpoints only.
2. **The demo API is not area-only.** The 3D city reads `/api/runs/{run}/stores`, `/suggestions`, `/owner-events` and `/days/{day}`: every shop's simulated hours, visits and next-week ideas, under real OpenStreetMap names. The notebook line in `GET /api/runs`, `GET /api/notebook` and `GET /api/agents/log` names the shop an experiment changed ("Opened Kebab Co till 03:00 → ...", see `tests/test_agents_training.py::test_offline_training_improves_and_stops_when_nothing_is_left`). Today only `/summary` and `/api/agents/session` are built and tested as anonymous area views. A council or landlord view must be a separate, area-only API.
3. **Benchmarks need 3 peers, not 5.** `insights.K_ANONYMITY` is 3; `docs/PMF.md` promises figures from at least 5 shops. With 3 peers the published median is the exact value of one of just 3 rivals (`tests/test_insights.py::test_benchmark_against_same_type_peers` asserts exactly that). Raising it to 5 would match the plan.
4. **Area sessions choose across shops.** The analyst picks which shops' own ideas to test together, scored on an area objective, and each shop's weekly report is its change in the area's best run. No shop sees another's plan, but the choice is area-wide. One-shop sessions (`POST /api/stores/{storeId}/optimize`) and the store page rank by the shop's own profit only. The competition-law review in `docs/PMF.md` is still to do before phase 2.
5. **Rejections bind the offline agent only.** The rejection filter (`backend/agents/store_owner.py:_owner_rejected`) runs on the offline path only. The Claude shop agent is told about rejections in its prompt, but code does not drop a rejected change it proposes again. An Approve does not update the shop's baseline either: decisions only steer next week's proposals.
6. **Licence data is assumed.** "Licensed hours" are default caps per shop type, widened to cover the venue's OpenStreetMap hours (`backend/pipeline/osm_map.py:_licence`). They are not read from Hackney's licensing register. There is no noise rule in code. The insights page keeps its own copy of the licence table (`backend/insights.py`); it matches `backend/agents/rules.py` today, but a change to one must be made in both.
7. **The spend cap is a pre-call check.** A call or batch already sent can pass the cap; one batch for 24 shops cost USD 0.14 (`docs/PMF.md`, 6.4). The ledger is a local file (`runs/costs.jsonl`), so deleting `runs/` resets it, and the caps are env settings. The Anthropic Console spend limit is the real backstop.
8. **Confidence measures stability, not benefit.** `report.seed_confidence` rates how consistently an effect keeps its sign across seeds, so a change that reliably costs the shop also reads "high". The impact numbers carry the sign. The store page says "going back is better"; the weekly report does not.
9. **Online report wording is guarded by a prompt.** When Claude writes a report's "why" paragraph, its source documents list every calibration venue by name (`backend/agents/report.py:_calibration_text`). Only the system prompt ("Never mention other stores") keeps other shops out of the PDF; no code scans the text. Today's calibration venues are placeholders ("Typical cafe"), so no real name is in them.
10. **Persona scrubbing is partial.** `scrub_usernames` removes `u/name` and `@handle` but keeps email addresses, and names in post text are left to the prompt. The raw Reddit cache (`data/raw/`, gitignored, never served) keeps post links. Reddit is not configured in this build, so this path has not run.
11. **The citizen model is in progress.** The parallel build adds synthetic profiles (age band, occupation, home street) and per-person diaries (`docs/CITIZENS.md`). They must keep the rule: no names, aggregate data only, nothing beyond a shop's own stats in its owner views. Extend `test_sim_citizens_are_synthetic_with_no_personal_fields` to the new endpoint.
12. **Incidents: open decision for the team, not policy.** The safety layer is a frontend mock (`docs/INCIDENTS.md`). The backend does not serve `/api/runs/{run}/incidents`, so with real data no incident is shown. If the backend ever serves it, attaching synthetic assaults or licence reviews to real, named venues would be a reputational and misuse risk. Options: keep incidents mock-only; serve them on fictional venues only; or serve an area density with no venue names. `test_the_backend_serves_no_incidents` fails the day the endpoint appears, so the decision cannot be skipped.
13. **One fail-open path is left.** `POST /api/apply` still applies suggestions without the hard rules if `backend/agents/rules.py` is missing (`backend/api/routers/training.py:_rule_checked`, a leftover from the parallel build). The module exists, so the path is dead today; removing it makes the API fail closed.
14. **The audit log is plain files.** `runs/*.jsonl` is not tamper-evident, and `runs/` is gitignored; the submission copy goes in `proof/`.

## Check it yourself

```
OFFLINE=1 .venv/bin/pytest -q tests/test_responsible_design.py
```

Each test in that file was also run against a deliberately broken copy of the code it guards (13 breaks, one per test, such as a summary that adds a per-shop cost breakdown or a GET that auto-approves). Every break made its test fail; the code was then restored.
